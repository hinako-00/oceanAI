# Ocean AI — AI営業コーチ兼クライアント管理アシスタント

アポメモ・録音の文字起こし・クライアント情報・過去のアポ履歴をもとに、営業担当者の
**次の一手を具体化する**社内向けアプリです。Claude API を利用しています。
複数人（営業チーム）での利用を前提に、メールアドレスとパスワードによるログインと、
チーム共有／本人限定の切り分けを備えています。

できること:

| 機能 | 画面 |
| --- | --- |
| アポ前の準備、アポ後の振り返り、営業相談、知識の学習 | コーチと相談 |
| クライアント役とのロールプレイ（終了後にフィードバック） | コーチと相談（右パネル） |
| クライアント情報を情報源つきで整理（確認済み／担当者報告／AI仮説／未確認） | クライアント情報 |
| アポメモ・文字起こしの記録とAI分析への受け渡し | アポを記録 |
| 次回行動（担当者・期限・目的）の管理 | 次回行動 |
| 担当者の強み・癖・改善点の蓄積（根拠と信頼度つき） | 自分の設定と営業傾向 |
| メンバーの強み・改善点を見て相談先を探す | チームの傾向 |
| 自社の商品資料・営業ルール・成功事例の登録 | 自社営業知識 |
| メンバーの追加・役割変更・無効化（管理者のみ） | メンバー管理 |

## セットアップ

```bash
npm install
cp .env.example .env.local   # ANTHROPIC_API_KEY を設定
npm run seed                 # 任意：デモのクライアント・アポ・知識を投入
npm run dev                  # http://localhost:3000
```

初回アクセス時は自動で `/setup` に移動し、**最初の管理者アカウント**を作成します。
以降は「メンバー管理」から営業担当者を追加してください（管理者が初回パスワードを設定し、
本人に伝えて、初回ログイン後に「自分の設定」で変更してもらう運用です）。

APIキーは [Anthropic Console](https://console.anthropic.com/) で発行します。
キーが未設定でも画面は開きますが、AIの応答だけが使えません。

チームで使えるURLとして公開する場合は [DEPLOY.md](./DEPLOY.md)（自前サーバー・Docker運用、HTTPS化）
または [NETLIFY.md](./NETLIFY.md)（Netlifyへのデプロイ、確認・すり合わせ向け）を参照してください。

| 環境変数 | 既定値 | 説明 |
| --- | --- | --- |
| `ANTHROPIC_API_KEY` | （必須） | Claude API のキー |
| `ANTHROPIC_MODEL` | `claude-opus-5` | 使用モデル |
| `ANTHROPIC_MAX_TOKENS` | `64000` | 応答の最大トークン数。下げすぎるとアポの分析が途中で切れ、保存候補も出なくなる（下記参照） |
| `DATA_DIR` | `./data` | データ保存先 |

## 誰が何を見られるか

複数人で使うため、共有すると価値が上がるものだけを共有し、個人的な相談内容は本人に閉じています。

| データ | 閲覧 | 編集・削除 |
| --- | --- | --- |
| クライアント情報・アポ履歴 | チーム全員 | 編集は全員／削除は担当者本人と管理者 |
| 自社営業知識 | チーム全員 | 追加・編集は全員／削除は登録者と管理者 |
| 営業傾向（強み・癖・改善点） | チーム全員 | 削除は本人と管理者 |
| 次回行動 | チーム全員（「チーム全体」タブ） | 完了・削除は担当者本人と管理者 |
| **AIとの相談履歴** | **本人のみ** | 本人のみ |
| メンバーの追加・役割変更・無効化 | 全員が一覧を閲覧 | 管理者のみ |

営業傾向はチームで共有する設定です。相談先を探したり勝ちパターンを共有するための情報であり、
人事評価の資料ではありません。AIによる観察には必ず根拠・分析データ数・信頼度が付きます。
少ないデータからの分析は「暫定的な傾向」として扱ってください。

退職・異動時はアカウントを削除せず**無効化**してください。過去のアポ履歴との紐付けが残り、
無効化した時点でそのメンバーのログインは即座に切れます。

## 認証の実装

- パスワードは scrypt でハッシュ化して保存します（平文もリバーシブルな暗号化も保持しません）。
- ログイントークンはランダムな32バイト。サーバーにはそのSHA-256ハッシュだけを保存します。
- Cookie は httpOnly / SameSite=Lax、本番（`NODE_ENV=production`）では Secure 付き。
- ログイン失敗が同一メールで5回続くと15分ロックします（プロセス内で保持）。
- パスワード変更・アカウント無効化・管理者によるパスワード再設定を行うと、
  その利用者の既存セッションはすべて無効になります。
- 未ログインのアクセスは `middleware.ts` で入口から遮断し、各APIでも `requireUser()` が再確認します。

## 設計上の約束

このアプリは「AIが言ったこと」と「クライアントが言ったこと」を混ぜないことを最優先にしています。

1. **情報源を必ず持つ** — クライアント情報の各項目は値と情報源（確認済みの事実／担当者からの報告／
   AIによる仮説）を分離できない構造（`lib/types.ts` の `CustomerField`）になっています。
   情報がない項目は推測で埋めず「未確認」のままにします。
2. **保存は人間の承認を経る** — AIは本文とは別に `save_proposal` ツールを呼んで保存候補を渡します。
   アプリはその入力を検証し（`lib/proposal.ts`）、担当者がチェックした項目だけを保存します
   （`lib/apply.ts`）。承認を経ない書き込み経路はありません。
3. **傾向分析には根拠を添える** — 担当者の傾向は、根拠・分析データ数・信頼度（低／中／高）と
   セットでのみ保存されます。データが少なければ信頼度は「低」＝暫定的な傾向として扱います。
4. **自社情報が一般論に優先する** — 「自社営業知識」に登録された内容は、一般的な営業理論より
   優先して参照するようシステムプロンプトで指示しています。
5. **ロールプレイ中は指導しない** — ロールプレイ中はクライアント役に徹する上書き指示が入り、保存候補の
   出力も止まります。終了操作をした時点でコーチに戻り、まとめてフィードバックします。

### 画面の作り（モバイルファースト）

スマートフォンでの利用（移動中・アポの直前直後）を前提に作っています。
CSSはメディアクエリなしの指定がそのままスマートフォン向けで、`min-width` で広い画面へ広げます。

| 幅 | ナビゲーション | 主な違い |
| --- | --- | --- |
| 〜767px | 上部バー＋ボトムタブ（5つ目は「その他」シート） | 表は1行=1枚のカード、副パネルはボトムシート |
| 768px〜 | 同上 | 入力欄が2カラムに |
| 1024px〜 | 左サイドバー（上部バーとボトムタブは非表示） | 相談画面は「履歴・本体・設定」の3カラム |

守っている約束:

- 押せるものは最低44px四方（`var(--tap)`）。入力欄の文字は16px以上（iOS Safariが勝手に拡大するのを防ぐため）。
- 押したら必ず面の色が変わる。`:hover` は `@media (hover: hover)` の中だけに書く
  （指で触る端末では、タップ後に hover が張り付いて色が戻らなくなるため）。
- 装飾の動きは `@media (prefers-reduced-motion: reduce)` で必ず止められるようにする。
  止めても位置と色は変えないので、意味は落ちない。
- 高さは `100dvh` を使う（`100vh` はモバイルのアドレスバー分だけずれる）。
- ノッチ・ホームバーの領域は `env(safe-area-inset-*)` で避ける。
- 横スクロールは出さない。広い表は `table.cards` でカードに畳む（項目名は `data-label` から出る）。

### 数字の見せ方

画面に出す数字は `lib/progress.ts` だけで作ります。保存も通信もしないので
`tests/progress.test.ts` でそのまま検証できます。守っている約束:

- **件数は行動の量で、成果ではない。** アポの結果とは並べない。並べると記録を盛る動機になる。
- **日付の区切りは端末のローカル時刻。** サーバー（UTC）で区切ると、日本時間の夜に
  入れた記録が前日に寄る。集計はクライアントで行い、APIは作成時刻をそのまま返す。
- **カルテは「埋まった項目数」ではなく「確からしさ」で数える。** 値があっても情報源が
  未確認のものは未確認として数える。AIの仮説だけで埋まったカルテを「確認済み」にしない。

グラフの色は、意味に合わせて使い分けます。

| 用途 | 色の役目 | 使うトークン |
| --- | --- | --- |
| カルテの確からしさ（確認済み＞担当者報告＞AI仮説） | ordinal（順序のある1色の濃淡） | `--ord-1` 〜 `--ord-3` |
| 未確認・未入力 | 色を持たせず下地として置く | `--bg-subtle` |
| 1系列の棒（曜日別の記録数、種別ごとの件数） | 1色 | `--accent` |

`--ord-*` は3案ぶん、light と dark それぞれで「単一色相・明度が単調・薄い端が下地から
2:1 以上」を満たすことを確認した値です。増やすときも目視で決めず、同じ条件で確かめて
ください。色だけで意味を運ばないよう、どのグラフにも数値の文字表示を必ず添えます。

### 配色（ブルーデザイン3案）

青を基調に3案を用意し、利用者が「自分の設定」画面で選べます。

| キー | 名称 | 性格 |
| --- | --- | --- |
| `navy`（既定） | ディープネイビー | 濃紺と強い罫線。一覧・表を数多く読む人向け |
| `ocean` | オーシャンブルー | 白地に澄んだ青。文字と背景の差が一番大きい |
| `sky` | ソフトスカイ | 水色寄り。角を大きく丸め、罫線を弱めた案 |

- 色の実体は `app/globals.css` 冒頭の `:root`（＝既定の navy）と `[data-theme='ocean' | 'sky']` にあります。
  3案とも light と dark の両方を持ち、端末のダークモードに追従します。
- 案の一覧・説明・見本の色は `lib/theme.ts`。画面に出す文言はここだけを直せば済みます。
- 選択値は端末の `localStorage`（キー `ocean-ai-theme`）に保存し、サーバーには送りません。
  チームの他の人の画面は変わりません。
- 初回描画のちらつきを避けるため、`app/layout.tsx` が `<body>` の先頭で
  `<html data-theme>` を先に書き込みます。キー名を変えるときは両方あわせて直してください。

個々の画面で色を直接書かず、必ずトークン（`var(--accent)` など）を使ってください。
直接書くと3案のどれかで読めなくなります。押した状態には `--press` / `--accent-press` を使います。

表をモバイルでカードにしたいときは `<table className="cards">` にし、各 `<td>` に
`data-label="項目名"` を付けます。カードの見出しにしたいセルは `data-head`、
操作ボタンだけのセルは `data-actions` を付けます。

### プロンプトを変更したいとき

`lib/prompt.ts` の `SYSTEM_PROMPT` がコーチの振る舞いのすべてです。
保存候補の構造を変える場合は、`lib/proposal.ts` の `SAVE_PROPOSAL_TOOL`（スキーマ）と
その下の検証、`tests/proposal.test.ts` を必ずセットで更新してください。
スキーマの列挙値と `lib/types.ts` の定義がずれると、モデル側は通るのにアプリ側の検証で落ち、
保存候補が黙って消えます（この一致はテストで守っています）。

### 推論の深さ（effort）

アポの振り返り（B）・営業相談（D）・傾向分析（G）は複数の記録を突き合わせる仕事なので
`effort: xhigh`、それ以外は既定の `high` で呼びます（`lib/mode.ts` の `effortFor`）。
モードはターンごとに入力から推定し直します。セッション作成時に固定すると、
途中で話題が変わったときに古い指示が残り続けるためです。

### データの保存先を変えたいとき

`lib/store.ts` がJSONファイルへの読み書きを閉じ込めています。DBへ移行する場合は
このファイルのエクスポート（`readAll` / `mutate` / `findById`）を差し替えれば、
上位の `repo.ts` 以降は変更不要です。

## 運用上の注意

- **HTTPSで公開してください。** パスワードとセッションCookieが平文で流れないようにするためです。
  リバースプロキシ（Nginx / Cloudflare など）の背後に置き、社内ネットワークやVPNに限定するのが安全です。
- データはローカルのJSONファイルに保存されます。**単一プロセスでの実行を前提**にしており、
  同一コレクションへの書き込みはプロセス内で直列化されます。複数インスタンスで動かす場合は
  `lib/store.ts` をDBに差し替えてください。
- `data/` ディレクトリにはクライアント情報とアポ内容が入ります。バックアップとアクセス権限の管理を行ってください。
  Gitには含まれません（`.gitignore` 済み）。
- サーバーレス環境へそのまま置くとデータが揮発します。
- AIの分析は入力された情報の範囲に限られます。アポの記録が少ない段階の傾向分析は
  必ず「暫定的な傾向」として扱ってください。
- パスワードの再設定は管理者が行います（メールによる自動リセットは未実装です）。
- 法令・契約条件に関わる判断は、必ず担当部門に確認してください。
